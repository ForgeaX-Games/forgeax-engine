为什么需要恢复工作流

主发布任务先报告 npm publish 成功，但公共 registry 仍短暂返回 0.1.4； carrier 版本和 tarball 都是 404。恢复任务没有重新构建 Engine，而是从已通过 ZIP verifier 的 Release 重建 carrier，再轮询公共 registry。这样可以区分 “发布请求完成”和“用户真的能下载”这两个状态。

@forgeax/engine-sdk 是 carrier，不是 CLI；CLI 由 @forgeax/engine 的 umbrella 入口提供。

不要双击 dist/index.html 或用 file:// 判断画面。 开发使用 pnpm dev，构建产物使用 pnpm preview 或 HTTPS 静态站点；HTTP 200 只证明服务存活，不等于 WebGPU 画面正确。

版本检查与升级风险

每次 forgeax new 都返回当前 SDK 与公共 registry 的版本判断：

{
  "status": "current",
  "currentVersion": "0.1.6",
  "latestVersion": "0.1.6"
}
  1. 发现新版本时先阅读 Release 的变更和迁移说明。
  2. 旧游戏保持原版本，不自动改写依赖。
  3. 在独立分支或复制目录中用新版 SDK 创建验证工程。
  4. 通过 doctor、tests、build、dev/preview 以及必要的浏览器/RHI 证据后再迁移。

升级可能涉及 API、资产 schema、插件 Entry 或构建工具变化；旧游戏需要自行适配。
